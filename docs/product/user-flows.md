# Пользовательские сценарии

Welcome → регистрация/вход → профиль → добровольный demo survey → consent → отправка 202 → pending → completed/failed. При явной угрозе правило возвращает предварительную рекомендацию независимо от доступности LLM. WS сообщает только идентификатор и статус; клиент запрашивает свой результат REST. При потере сети pending polling восстанавливает состояние.

«Продолжить сессию» выполняет refresh по явному действию пользователя, без показа сохранённых ответов на welcome. Logout отзывает серверную refresh-сессию и очищает локальный access. Токен access может оставаться действительным до TTL; история браузера автоматически не удаляется. Скомпрометированное устройство не считается защищённым.

Отдельный external consent по умолчанию выключен. Никакого автоматического контакта с третьими лицами, специалистом или экстренной службой. Support catalogue и участие подготовленного специалиста появятся только после реальной организационной подготовки.
